현재 코드에서 무엇을 정했나

본선 한 경기에서 M1~M6를 한 대의 UGV로 수행합니다. 이 문서는 현재 코드의 행동 상태, 전이 조건, 명령을 내리는 순서를 첨부한 원본의 형식으로 정리했습니다. 기본 전략은 지정 표적 수행, 객체 탐색, 적 UGV 회피와 목표 거점 진입입니다.

현재 구현행동 상태는 Mode 11개입니다. STRIKE의 접근·조준과 EXPLORE의 이동·관측은 내부 단계이며, 회피 수준과 장치 잠금은 별도로 관리합니다. HUNT는 구현돼 있지만 기본 설정은 OFF입니다.

M2와 M4의 공용 탄약

읽을 때 구분할 세 가지

1. 경기 단계와 행동 상태P0~P4는 설명을 위한 경기 단계입니다. 코드에 같은 이름의 상위 Enum이 있는 것은 아닙니다. 실제 행동은 WAIT, EXPLORE, STRIKE 등의 Mode로 표시합니다.
2. 행동 상태와 출력 선점회피가 실행돼도 Mode 이름이 바뀌지 않을 수 있습니다. 같은 순간에 어느 로직이 주행 명령을 내리는지 함께 보아야 합니다.
3. 현재 구현과 개선 제안초록색 안내는 현재 구현을, 노란색 안내는 실측·운영 확인 또는 제안을 뜻합니다. 제안한 M3 구역별 완료 관리가 이미 구현됐다는 의미는 아닙니다.

경쟁 상태와 지연 경계

다음 항목에는 스레드 경쟁뿐 아니라 같은 tick의 처리 순서, 늦은 응답, 이전 목표의 잔여 명령이 포함됩니다.

ID · 상황현재 방어남은 문제 / 수용할 개선
R01 · STOP과 제출 재시도HALT에서 M1~M5 폐쇄, 토큰별 ACK 추적.재현 폐쇄보다 update가 먼저다. STOP 판정·출력 0·제출 폐쇄를 새 제출 전송보다 앞에 둔다. 이미 전송된 요청은 응답만 기록하고 서버 판정을 따른다.
R02 · STOP과 느린 작업센서 처리보다 서버 poll을 먼저 수행. 비동기 링크·검출기 경로 존재.같은 tick에서 동기 깊이 처리·일부 호출이 길어지면 다음 STOP poll이 늦어진다. 제어 주기 상한·watchdog·작업 분리 검증이 필요하다.
R03 · 취소된 Nav2 목표의 결과·속도목표 세대 번호, 취소, CmdCache 게이트. 목표 수락 전 명령을 차단.일반 Twist에는 goal ID가 없다. 새 목표 수락 뒤 도착한 이전 속도를 완벽히 구분한다는 뜻은 아니다. 실제 ROS 지연·취소 경계 시험이 필요하다.
R04 · 오래된 영상과 새 자세프레임 stamp, 촬영 시점 자세, 중복 검출 폐기, 비동기 결과의 원본 프레임 연결.각 센서의 실제 시계 차이·지연을 측정해야 한다. 신선도 기준만 맞아도 기하 보정이 틀릴 수 있다.
R05 · 중복 START / 다른 경기 이벤트START 1회, STOP 종단 래치, 제공된 match_id·seq 검증. 새 Agent 생성.메시지에 ID가 없으면 다른 경기의 늦은 이벤트를 완전히 가릴 수 없다. 로컬 종료와 외부 큐·SLAM 초기화를 함께 정의해야 한다.
R06 · 늦은 M1 LLM 응답명령 버전 _cmd_ver 비교. 오래된 응답 폐기.이미 요청·제출한 M1을 갱신할 수 있는지는 API 확인. “started”와 “acked”를 UI·로그에서 구분해야 한다.
R07 · 회피와 조준의 동시 출력회피 선점 시 이전 목표 취소·조준 리셋·발사 중단 요청. 선점 tick은 임무 실행을 건너뜀.laser_abort 미지원 또는 펌웨어 지연이면 즉시 소등은 보장되지 않는다. 회피 해제 후 과거 표적/경로를 새 관측으로 검증한다.
R08 · 피격 이벤트와 장치 상태 지연0.6초 유예 잠금과 하드웨어 disabled/drive_paused 값을 병합.장치 상태가 0.6초보다 늦으면 잠금 공백 가능. 이벤트 중복·누락·카운터 재시작, 실제 10초 잠금 유지 확인.
R09 · M5 전환과 RECOVER·회피GOAL에서 출발한 RECOVER는 끝까지 진행. 회피 선점·복구 출발 상태를 따로 관리.GOAL/STAGE는 선점 면제지만 GOAL에서 출발한 RECOVER 자체는 Mode.RECOVER다. 가까운 적 회피가 복구를 다시 선점하는 경계를 시험해야 한다.
R10 · 거점 도착 추정과 서버 종료로컬 진입 추정은 0속도 대기만 수행. STOP/finished가 종료 판단.틀린 거점 추측 또는 TF 오차로 잘못 기다릴 수 있다. 대기 시간 상한·표지 재관측·거점 신뢰도 상태가 필요하다.
R11 · M2 완료와 다음 표적 면 선택사격하던 면의 LED를 먼저 검사하고 완료를 래치.같은 종류 다른 표적·박스 이동·배정 팀의 득점을 구분할 안정적인 ID가 필요하다. 현재 target_hit 이벤트는 by만으로 완료 처리하는 경로가 있다.
R12 · 센서는 복귀했지만 위치는 오래됨스택 초기화 여부·새 LiDAR 표본 수 확인. Nav2 조회 실패 때 대체 경로 존재.TF가 조회 가능하다는 사실과 최신 자세라는 사실은 다르다. map→base 시각·위치 불확실성까지 안전 복귀 조건에 포함할 것을 제안한다.
