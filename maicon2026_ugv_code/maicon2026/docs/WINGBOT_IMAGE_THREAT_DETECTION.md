# WINGBOT 영상 기반 위협 후보

시뮬레이션 검출기만 확장했다. 실기 기본 설정에는 연결하지 않는다. 로봇 이름, Gazebo 자세, 경기장 배치, Frame의 모의 검출 메타데이터를 읽지 않는다.

- 지상 RGB: 같은 팀 색의 안테나 슬리브 두 개와 그 아래 실제 흰 수광 돔을 함께 확인한다. 은색 명판을 돔으로 고르지 않도록 높이 범위를 제한한다. 두 슬리브가 가려지면 추정으로 소속을 채우지 않는다.
- UAV RGB: 측정된 격자 캘리브레이션으로 슬리브 높이 0.217m에서 픽셀을 투영한다. 두 슬리브 간격 0.214m, 회색 차체, 높이 0.122m의 두 수광 돔 영역을 확인한다. 검은 밴드가 슬리브를 나누어도 같은 로봇을 중복 보고하지 않는다.
- 위치는 관측된 안테나 쌍의 중점이다. 차체 중심보다 뒤로 약 4cm 치우치며, 보이지 않는 차체 방향을 Gazebo 정보로 보정하지 않는다. 반환값에 개별 로봇 ID를 넣지 않는다. 초기 거점·시간 연속성에 따른 기존 추적기가 관측만으로 연결한다.
- HttpServerLink의 uav_robot_detector는 명시적 선택 기능이다. JPEG를 실제로 해독한 후 촬영 시각과 나이를 검사한다. 오래되거나 잘못된 영상·좌표는 빈 결과로 남기며 LiDAR 경로를 막지 않는다.

실제 Gazebo 출력 두 장을 tests/fixtures에 보관했다. RED 로봇 근접 사진은 네 축척에서 수광 돔 픽셀까지 확인했다. 여섯 WINGBOT 시작 장면은 원본 PNG와 JPEG 품질 100/95/90/85에서 각각 BLUE 3대와 RED 3대를 검출했고 경기장 표시 오탐은 없었다. 품질 75에서는 B2 한 대를 놓쳤다. 이는 한 시작 장면과 한 근접 사진의 검증이며, 움직이는 전 경기·가림·실물 조명에서의 검출률을 보장하지 않는다.

재현: python -m pytest tests/test_wingbot_robot_vision.py tests/test_wingbot_image_detector.py

새 위협 후보는 비용 지도에 활용한다. LiDAR만으로 소속을 확정하지 않으며 미상·아군에게 발사하는 근거로 쓰지 않는다. UAV 라벨은 5초가 지난 뒤 신뢰도가 낮아지고, LiDAR 위치 갱신이 오래된 팀 색을 새 관측으로 갱신하지 않는다.
