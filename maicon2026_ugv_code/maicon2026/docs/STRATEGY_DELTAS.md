# API 반영에 따른 전략 경계와 변경

이번 API 작업은 기존 회피 우선순위와 회피 임계치를 바꾸지 않는다.
관찰값과 심판의 정답을 분리하고 공식 제출·채점 규칙을 연결했다.
요청된 후반 자기 거점 진입 방지 정책은 별도 경로 제약과 최종 속도 제한으로 추가했다.
전체 및 ZIP 내부 회귀는 아직 완료되지 않았다.

## 제출 동작의 변화

- M1: 명령 수신 뒤 규칙 해석을 먼저 제출한다. 제한 시간 내 유효한 LLM 해석이 오면 세 항목을 통째로 정정한다. 늦거나 이전 명령의 결과는 무시한다.
- M3: 확정 관측만 집계하고 매번 채점구역 전체본을 보낸다.225초 이후 변경된 전체본의 최소 간격을1초로 줄였다. 정정으로 수량이 감소하는 경우도 반영한다.
- M6: 경기 중 갱신한 관찰 추정을 reporting 즉시 제출한다. 시간 안에 준비된 유효 LLM 결과는 선택적 정정에 쓰며 첫 보고를 지연시키지 않는다.
- 중간 재시작: 서버 시간 복구를 시작 거점으로 위치 복구한 것으로 취급하지 않는다. 실제 CLI는 지도·앵커 없는 running 재시작을 정지 상태로 거부한다.

## 기존 테스트를 고친 이유

기존 테스트를 삭제하거나 검증 조건을 줄이지 않았다.
`test_real_runtime.py`는 Config 직접 생성에서 실제 `load_run_config` 진입점으로 fixture를 맞추고,
항상 AsyncServerLink 정책·비밀값 환경 입력·실제 child.send_signal 종료 경로를 검증한다.
임무코드를 명령행에 넣던 호출과 동기 링크 선택은 새 불변식에 맞춰 제거했다.

`test_uav_image_only.py`의 단독 UAV 관측 fixture는 `goal_base_types={}`로 M5 자동 종료를 끈다.
공식 M5가 진영 공통 센서 점령으로 수정되면서 관측 시험이 먼저 끝나던 간섭을 분리한 것이며 기존4개 관측 assertion은 보존했다.
실제 M5 규칙은 `test_spec_game_rules.py`에서 별도 검증한다.

기존 낮은 장벽 시험의 실패를 독립 실행으로 조사하면서 Python World가 긴 장애물의 중심에서0.6 m보다 먼 접촉을 검사하지 않는 결함을 확인했다. `_resolve_rect`의 사전 검사를 실제 장애물 경계와 회전한 차체 경계로 바꾸고, 긴 벽 끝을 관통하지 않는 직접 물리 회귀를 추가했다. 또한 M5 도중 SAFE_STOP 뒤 무조건 EXPLORE로 돌아가던 결함을 고쳤다. 복귀 시 현재 M5 게시·마감으로 GOAL/STAGE/EXPLORE를 다시 판단하고, 회피 제어의 기존 `in_goal` 조건을 같은 틱에 갱신한다. 오래된 조준·경로는 복원하지 않는다. 회피 임계치·우선순위와 두 기존 성능 assertion을 유지한 채 두 시험 모두 선택 재검증에서 통과했다. 전체 회귀 완료는 별도다.

`test_real_uav_frame_is_restamped_to_robot_clock_for_tracker`의 spy는 현재 tracker 호출의 `self_ident` 키워드를 받도록 맞췄다. 원래 시각 변환 assertion을 유지하고 `B-UGV-2`가 실제로 전달되는지 추가 검증한다. tracker 구현은 바꾸지 않았다.

M2 전체 회귀에서 같은 종류의 아군 표적을 파괴한 기록만으로 완료를 판정하던 결함을 확인했다. 점수는 이미 상대 진영의 지정 표적 파괴 여부를 확인하고 있었으므로 채점식을 바꾸지 않았다. `Agent._opponent_target_face`는 실제 관측으로 만든 표적 중심·종류와 알려진 진영 경계를 사용하며, 실측 경기장도 명시적으로 변환된 nav 좌표에서 판단한다. 조준 검출은 촬영 시점의 자세·팬·거리로 투영해 현재 선택한 면의 기존 관측 합치기 거리 안인지 확인한다. 같은 종류라는 이유만으로 화면 중앙의 다른 표적을 겨냥하지 않는다.

선택한 상대 표적에 대한 자기 발사, 종류, 진영이 맞는 로컬 장치 이벤트만 완료에 쓴다. 이벤트가 별도 장치 ID를 포함하면 관측으로 아는 ID와 일치해야 한다. 비공개 referee 배치 인덱스는 관측 ID로 취급하지 않는다. 종류·진영이 없는 이벤트는 완료를 확정하지 않으며, 공식 API에 없는 파괴 조회를 새로 만들지 않는다. 기존 연속 LED 확인 경로는 그대로 사용할 수 있다. `test_spec_runtime`의 미확인 이벤트 fixture는 완료를 기대하지 않도록 바로잡고 M2/M4/M5 참가팀 POST가 없다는 검증을 유지했다. 새 `test_m2_target_scope.py`는 두 경기장 좌표계·양 진영·잘못된 이벤트·선택 면의 영상 결합을 검사한다. 표적 범위·규칙·런타임 선택 검사59개가 통과했다(7.12초).

이후 lattice seed3은 상대 표적을218.3초에 발견하고222초 사전 이동에 선점되어0발로 끝났다는 별도 원인을 확인했다. 이미222초 전에 시작한 유효 M2만 감지 지도의 접근 경로·조준·센서 탐색·전체5초 발광·staging 복귀 시간을 계산해 마무리할 수 있다. 연속 수광2초만 예약하고 실기에서 발광을 중간에 끌 수 있다고 가정하지 않는다. 탐색과 같은 경로 시간 모델 및 기존 `stage_margin_s`를 쓰며, 한 번 정한 마지막 발사 시각은 연장하지 않는다. 새로운 늦은 교전, 지연된 재발사, 불통 복귀 경로는 허용하지 않고 실제 M5 게시·STOP·전체 마감·안전/회피 우선권을 유지한다. 점수와 회피 임계치를 바꾸지 않았다.

최종 선택 검사58개가 통과했다(62.30초, `tmp/m2_final_focus.log`). `test_m2_completion_budget`, `test_m2_target_scope`, `test_safe_resume_context`, `test_spec_runtime`과 기존 lattice M2/M5·온라인6시드 M2 시나리오를 포함한다. 이벤트 없는 LED 시나리오는 앞선 표적 귀속 수정 후 별도 통과했으며 이58개에 합산하지 않는다. **Python 시뮬레이션의 이 결과는 새 Gazebo 경기장의 자율 M2/M3 성공 결과가 아니다.** 새 UAV 영상의 큐브20/20 형상 후보는 M3 종류를 알려 주지 않으며, 실제 근접 사진 분류·면 확인·Nav2 전체 경기 시험은 남아 있다.

배포 후보의 전체 회귀에서는 전방 차단 시험이 다시 실패했다(회피 사용5피격, 기준선2피격). 시각별 재현 결과 추가 피격은72.7~199.6초로222초 M2 완료 창 이전이었다. 시험의 상대는70초에 등장하도록 정의됐지만 `Hostile` 생성 즉시 `World.ugvs`에 등록되어 R-1의 주차 위치가 LiDAR·영상·UAV에 노출됐다. 회피 사용 시35.1초부터 이 미래 상대를 피했으므로70초 이전 경로와 상대의 등장 위치까지 달라졌다. `spawn_rel`로 지연 등장하는 상대만 실제 배치 성공 전 월드에서 제외하고 성공 시 한 번 등록하도록 고쳤다. 거리·노출 지표에서도 아직 존재하지 않는 상대를 제외한다. 원래부터 존재하며 행동만 늦추는 상대는 물리 로봇으로 유지한다.

이 수정은 회피 전략·임계치·등장 시각·거리·기존 assertion을 보존한다. 기존 전방 차단 시험은 그대로 통과했다(59.55초). 새 `test_hostile_spawn.py`5개도 통과했다(4.42초): 등장 전 센서/충돌/UAV 부재, 정상 등장, 배치 실패와 재시도, 단일 등록, trigger 상대 시각, 기존 물리 로봇 보존. 후속 ZIP 전체 회귀는 별도 기록한다.

## 후반 자기 거점 보호 — G12/S9.7

공식 규칙은 센서가 UGV의 소속을 구분하지 않으므로 자기 거점을 가리면 상대 점령을 도울 수 있다는 것이다. 이를 피하려고 요청된 `mission.forbid_own_bases_at=225.0`부터 자기 진영 세 거점에 계획 제약을 적용한다. 음수 값은 이 전략을 명시적으로 끈다. 상대 거점은 이 제약으로 차단하지 않으며 좌표는 현재 `ArenaGeometry`에서 읽는다. 실측 YAML을 쓰면 같은 좌표 변환을 따른다.

계획 마스크는 차체 외접 반경·위치 오차 여유·격자 반칸 대각선을 포함한다. LiDAR 점유지도나 M3 상자 관측에는 쓰지 않는다. 활성화 시 경로 캐시를 비우고 builtin 경로를 다시 계산한다. Nav2에는 앵커를 적용한 축 정렬 `/own_base_keepout_mask`와 `/own_base_keepout_info`를 발행하며, local/global costmap의 KeepoutFilter가 받는다. 마스크 소비자가 확인되지 않으면 동일 제약을 가진 내장 플래너로 전환한다. 새 경기의 빈 마스크는 이전 제약을 해제한다.

최종 출력 제한은 가속 램프 이후의 명령에 적용한다. 직진·회전 중 차체 모서리까지 검사하고, 이미 거점과 겹친 상태에서는 경기장 쪽으로 빠져나가는 동작을 허용하면서 더 깊이 들어가는 동작은 막는다. 구속에서 완전히 벗어나면 임시 탈출 통로를 닫는다. `own_base_guard_horizon_s=0.5`와 `own_base_guard_step_m=0.01`은 명령 예측과 수치 샘플링 설정이며 공식 경기 규칙이나 실측 제동 성능이 아니다.

2026-11-09 선택 회귀는 `test_spec_field_policy`, `test_spec_conformance`, `test_nav_stack`, `test_exploration_continuity`, `test_real_runtime`, `test_gazebo_api`, `test_mockserver_spec` 관련 138개가 통과했다. BLUE/RED 경계 시각, 측정 YAML 좌표, 내부 탈출, 차체 회전 모서리, Nav2 앵커 회전, 마스크 해제, 미지원 전송의 대체 경로, 최종 출력 제한을 포함한다. 실제 ROS Nav2 필터 수신과 동적 주행, 실물 제동거리는 별도 검증이 필요하다.

기존 M3 persistence fixture의 사진은 관측 큐브 면과 동기화한 뒤 집계한다.
확정되지 않은 옛 비정합 기록을 추가 객체로 세지 않도록 한 일반 중복 방지 계약을 따른다.
