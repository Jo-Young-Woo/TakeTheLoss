# M3 관측점 도착 검증 (candidate05)

항법의 `reached`만으로 M3 관측 단계에 진입하지 않도록 수정했다.
`progress.enabled=True`인 온라인 얼굴 탐색에서만 적용하며 v2와 프런티어·
survey 동작은 유지한다. 실제 추정 정차 위치에서 관측 장부의 해당 면을
기존 `CoverageMap.face_visible`로 다시 검사한다. 70° 입사각, 최소 0.4 m
거리, 최대 거리, 시야와 가림 기준을 완화하지 않는다. 사진 면으로 확인된
경우에는 기존의 더 엄격한 `picture_visible` 기준을 그대로 사용한다.

정차 위치가 부적합하면 가까운 보정 관측점 하나만 시도한다. 기존 계획점
25 cm 이내·현재 위치40 cm 이내에서, LiDAR가 확인한 자유 공간에 회전
차체 외곽과 기존 계획 여유가 들어가고 목표 제외 정책도 통과해야 한다.
보정점 주변4 cm에서도 기존 가시성 검사를 통과해야 하며 도착 허용 거리는
3 cm, 보정 시간은 최대3초다. 이후 실패하면 해당 시점을 잠시 제외하고
재선택한다. 실패를 관측·분류·도착시도·임무진전으로 올리지 않는다.
이 보수적 보정 여유는 새로운 관측 인정 기준이 아니며, 최종 실제 위치는
항상 기존 조건으로 다시 검사한다.

`primary_face`가 없는 기존/갱신 후보도 버리지 않는다. 후보가 가진 관측
장부의 면 중 원래 계획한 카메라 방향에 가장 가까운 면을 복원한다.
현재 위치에서 우연히 가장 가까워진 다른 박스로 목표를 바꾸지 않는다.

저장된 candidate03 B2 좌표를 이용하면 계획점은 기존 관측 범위에 들지만
허용된16.5 cm 이른 정차가 관측 범위를 벗어나는 일반적 결함을 재현할 수
있다. 다만 이 재현은 저장된 ObjectMap 얼굴 좌표를 FaceRec으로 옮긴
단위시험이다. 당시 도착 시각의 장부 좌표는 기록되지 않았고, 210초 장부
좌표를 쓰면 같은 정차점이0.436 m /69.85°로 간신히 통과한다. 따라서
이 패치가 당시 B2 미탐 원인을 입증했거나 그 미탐을 해결했다고 주장하지
않는다. 실제 경기 전체의 M3 탐지율 향상도 아직 검증하지 않았다.

후속 실제 기록용 `agent._m3_arrival_events`는 최대128건을 보관한다.
각 사건에는 실제 추정 위치, 선택한 면 키와 관측 장부 기하, 원래 계획점과
거리 오차, 기존 가시성 검사의 결과/이유, 보정 목표와 최종 동작이 담긴다.
지도 정답이나 실제 로봇 위치를 제어기에 넣지 않는다. 기록은 제어 계산에
재사용되지 않는다.

검증: `tests/test_m3_face_arrival.py`의17개 시험 통과. 거리·입사각·가림·
사진 시야 기준, 보정 성공/실패/시간 제한, 미관측 공간과 제외 목표,
장부 수치 불변, 목표 면 복원, legacy 유지, 사건 기록 상한을 확인한다.
검증 fixture의 자유 공간은 합성이므로 실제 경기의 같은 위치에서 보정점이
존재한다고 해석하면 안 된다. 후보까지 도달하지 못하는 경로 문제와
미선택 면의 시간 배분은 별도 과제다.
