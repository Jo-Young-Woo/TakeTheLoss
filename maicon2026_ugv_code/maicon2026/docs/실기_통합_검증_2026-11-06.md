## 실제 ROS2 프로세스 기동 검사

WSL Ubuntu 22.04 / ROS2 Humble, localhost 전용 ROS domain 187에서 실행했다.

- Cartographer 설정 파싱, Nav2 노드 생성, launch 인자 및 `RewrittenYaml` 중첩 프레임 변경 성공.
- `/cmd_vel`은 발행자 0개. 팀 HAL이 마지막 명령을 발행할 수 있도록 overlay가 직접 주행 토픽을 점유하지 않음.
- `/cmd_vel_nav2`는 controller/behavior만 발행. `/odom`·`/scan` 발행자 0개로 드라이버를 중복 기동하지 않음.
- 실제 센서를 넣지 않았으므로 TF 대기 상태였다. Nav2 활성화·지도 품질·주행 성공은 검증하지 않았다.
- 이 무센서 대기 상태를 SIGINT로 종료할 때 Humble `controller_server` lifecycle context 오류(-6)가 남았다. 부모 launch에만 SIGINT를 보내도 재현되었다. 실제 센서가 연결된 활성화/종료 흐름은 별도 확인이 필요하다.

원시 로그는 로컬 저장소의 `review_2026-11-06/integration/`에 보관하며 Git 제외 대상이다. `pytest-integration.txt`, `pytest-final-focused.txt`, `pytest-final-contract.txt`, `ros_hardware_smoke.log/json`을 참조한다.

## 현장 전제와 남은 기능

- 팀의 학습된 YOLO 가중치, 실제 LLM 어댑터/모델, 운영진 ROS 환경과 서버 인증이 필요하다.
- 깊이 카메라 토픽·내부/외부 보정값이 검증되지 않아 실기 기본 프로필에서는 깊이/복셀 입력을 비활성화했다.
- UAV JPEG 수신은 구현했지만 영상에서 경기장 좌표를 계산하는 처리는 구현하지 않았다.
- 경기 도중 새 프로세스는 지도·앵커·장부가 복원되지 않으므로 임무 시작을 차단한다. 시계 저장만으로 자동 재개하지 않는다.
- 마찰·슬립·정지거리·센서 장착·차체 진행축·카메라/레이저 시차는 실제 로봇 측정이 필요하다.
