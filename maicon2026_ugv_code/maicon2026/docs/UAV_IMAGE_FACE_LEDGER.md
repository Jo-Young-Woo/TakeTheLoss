# UAV 원본 영상과 면 장부

2026-11-12. 실제 UAV 시점 RGB 프레임에서 장애물을 검출하여 면 목록을 생성한다. 원근 시점을 유지하며 LiDAR 지도 그림으로 대체하지 않는다.

## 현재 카메라

실행 중인 Gazebo 월드에서 확인한 고정 카메라 pose는 (0,0,2.5, 0,π/2,π/2)이다. 중앙 원점 world 좌표에서 높이 2.5m, 수직 하향이다. 경기장 좌하단 원점으로는 (3.0,2.4,2.5)m, 수평 화각 130°, 1280×720, 1 Hz다. 실제 대회 설치 위치를 실측했다는 의미는 아니다.

임무용 /uav/image_raw는 1 Hz를 유지한다. 녹화는 같은 pose·화각·해상도의 실제 Gazebo 카메라를 별도로 30 Hz로 렌더링한다. 기존 validation_camera의 위치를 실행별 프로파일에서 UAV와 일치시키고 /arena/validation/image_raw를 녹화한다. 낮은 주기의 영상을 반복해 움직임을 만드는 방식이 아니다. 분석용 면 장부는 이 영상에서 1초 간격으로 갱신한다.

24개 격자 대응점(23개 인라이어)과 별도 검증점 23개를 쓰는 기존 보정을 유지했다. 바닥 투영(z=0)과 박스 윗면 투영(z=0.4m)을 분리한다. 상공 카메라도 원근 투영이므로 두 경계의 영상 위치가 다르다.

## 영상 → 장부

1. RGB 프레임을 보정된 윗면 평면에 투영하고 사각형 윗면을 추출한다. 색·모양 조건은 현재 Gazebo 경기장에 맞춘 검출기이며 실사 범용 모델은 아니다.
2. 서로 다른 촬영 시각의 연속 영상에서 위치/크기가 일치한 후보를 받아들인다. UAV 영상에서 검출한 UGV 위치를 제외한다. 이 단계에는 LiDAR, 오도메트리, Gazebo 장애물 좌표를 넣지 않는다.
3. 영상 중심·크기를 따로 보존한다. 지상 LiDAR가 중심이나 크기를 보정해도 원본 UAV 기하를 덮어쓰지 않는다. UAV 면 지도에는 LiDAR로만 발견한 상자를 넣지 않는다.
4. 맞닿은 변의 구간을 합쳐 내부 부분을 제외하고 노출 선분을 남긴다. U01-E/N/W/S처럼 영상 장부 ID를 부여하며, 선분의 경기장 좌표·원본 이미지 픽셀·방향·촬영 시각·가림 정보를 기록한다. 독립 영상 장부와 Agent 박스 번호는 다를 수 있다.
5. 윗면 윤곽으로 예상한 옆면은 side_identity_unobserved다. 카메라 쪽으로 향한 면도 가림이 검증되지 않았으므로 side_visibility=unverified다. 보이지 않는 옆면을 식별/빈 면으로 완료하지 않는다.
6. Agent의 지상 관측 결과는 원본 UAV 중심·크기·면 방향이 유일하게 일치할 때 ground_state로 별도 연결한다. 촬영 시각보다 미래의 결과나 3초 넘게 오래된 장부는 사용하지 않는다. 이 연결은 영상 장부의 기하 또는 M3 점수에 자동 반영되지 않는다.

현재 구현은 상공 윤곽으로 관측 대상 면 목록을 만드는 기능이다. UAV 옆면 사진에서 M3 클래스를 직접 분류하는 새 모델이나 모든 면 가시성 판정까지 구현한 것은 아니다.

## 녹화

기존 ROS/Gazebo 환경을 준비한 뒤 다음처럼 실행한다. 기본 3인칭 녹화는 유지되며 UAV 시점은 명시적으로 선택한다.

기본값은 6대다. B-2 한 대만 배치할 때는 --ugvs 1을 추가한다. 단독 5분 시험은 --ugvs 1 --duration 300으로 실행한다. 나머지 로봇 모델과 제어 프로세스는 생성하지 않는다.

M5 거점 점령은 5분 전에 경기를 종료시킬 수 있다. 실행기는 임무가 조기 종료돼도 지정한 duration까지 실제 카메라 녹화를 유지한다. 종료 후 면 장부는 FINAL 표시와 관측 시각을 남기고 최종 상태를 보존한다. 이 구간은 경기 종료 후 화면이며 새로운 탐색이나 식별로 세지 않는다.

```bash
python3 scripts/run_wingbot_selfplay.py --output results/새로운_출력_폴더 --duration 60 --seed 0 --variant progress --scenario selfplay --record-view uav --uav-video-fps 30 --render-device cpu --ros-domain-id 180 --ready-timeout 180 --wall-timeout 1200
```

- uav_native_rgb.mp4: 실제 UAV 시점 RGB, 1280×720, 기본 30 fps. 수신 프레임 주기와 누락 여부는 recording.json으로 확인한다.
- uav_image_face_ledger.mp4: 같은 프레임 위에 면 경계와 장부를 표시한 1700×720 영상.
- uav_image_face_ledger.jsonl: 각 촬영 시각의 장부. 같은 이름의 JSON은 마지막 스냅샷.
- uav_camera.json, uav_recording_profile.yaml: 카메라 위치/시야각/영상 주기, 실행용 프로파일 및 보정 검증 결과.
- *.recording.json, *.frames.jsonl: 실제 수신·출력 프레임 수, 촬영 시각, 동일 프레임 유지와 누락 여부. 시뮬레이션 시간을 기준으로 저장하며 장면이나 움직임을 합성하지 않는다.

노란 실선은 윗면 외곽(z=0.4m), 청록 점선은 같은 장애물의 바닥 투영(z=0), 자홍 십자는 UAV 바로 아래 지점이다. 장부 ?는 옆면 그림 미확인, X는 제외 면이다. ground 열의 I/E는 별도로 연결한 지상 식별/빈 면 관측 상태다.

## 섹터별 집계

UAV에서 얻은 박스 중심을 경기장 실측 섹터에 배정한다. CM은 내부 이름 COMMON과 같다. 섹터 밖은 OUTSIDE로 남긴다. 면 4개를 박스 4개로 세지 않고 영상 박스 ID를 기준으로 중복을 제거한다.

- BOXES: UAV 영상으로 위치·형상을 확인한 박스 수.
- WITH I: B-2의 지상 관측에서 유효 옆면 하나 이상이 identified인 박스 수.
- ALL I/E: 제외 면을 뺀 모든 옆면이 identified 또는 empty인 박스 수. U/H/미관측 면은 완료로 세지 않는다.
- U01:1/3: 해당 박스의 유효 면 3개 중 1개가 식별됐다는 뜻이다. U01은 식별 불가 기호가 아니라 박스 번호다.

영상 장부는 B-2의 관측만 연결한다. 여섯 로봇 합산이나 공식 M3 점수와 같지 않다. UAV 윗면 검출만으로 옆면 그림을 식별했다고 보지 않는다.

이 WSL 장치의 D3D12 GPU/Ogre2 조합에서는 텍스처가 있는 경기장·박스가 사라지는 현상을 실영상으로 확인했다. 따라서 검증한 CPU 렌더링을 기본으로 사용한다. GPU 시험은 --render-device gpu로 명시할 수 있으나, 실제 RGB에서 모델·텍스처가 정상인지 먼저 확인해야 한다.
