# M3 전장객체 탐색 + 적 UGV 회피 — 하나의 항법 구조로 (설계 · 구현 · 검증)

> 기준: `maicon26/` 최신 코드. 시뮬 수치는 **실기 성능이 아니다**. 실제 YOLO 가중치·UAV 영상 검출기·실기 API가 없어서 그 입력은 시뮬이 주는 라벨(오판 4 %, 누락 5 %+4 %/m, UAV 위치 σ 0.04 m·지연 0.4 s)로 대신했다. 이 문서의 `[가정]`은 실측 전까지 믿지 말 것(목록은 §7, 값은 `field/FIELD_CHECKLIST.md`).
> 이전 설계 문서: `docs/적UGV_회피_설계서.md`(코드 수정 전 설계). 이 문서는 그 설계 중 **구현한 부분과 달라진 부분**을 적는다.

## 0. 한 장 요약

| 항목 | 결과 |
|---|---|
| 지켜진 제약 | A*(`nav/grid.py astar`)와 Nav2 전역 계획기는 그대로. 임무 계층이 *다음 관측 시점/안전 경유지*를 고르고, 계획은 기존 Nav2/A*, 안전 계층(LiDAR 정지·SAFE_STOP·STOP/HALT)이 최우선 |
| M3 | 고정 5×5 순회 → **온라인 탐색**(프런티어 + 면 단위 다음 최선 시점, 면 장부). 기본값 `explore.strategy="online"`, `"lattice"`로 즉시 복귀 가능 |
| 적 회피 | 카메라/UAV/LiDAR 동적 군집 → 위협 보드 → 시간 층 위협장 → 회피 제어기(AWARE/EVADE/CLOSE). M4는 계속 OFF |
| 정직한 결과 | M3: 면 장부 *집계*가 정밀도를 올렸고(0.82→0.99), 온라인 *탐색* 자체는 재현율이 고정 순회보다 낮다(0.835 vs 0.890) — 이동거리 −7 %, 충돌 감소. 회피: 적이 쏠 때 피격이 크게 줄었으나(S1 정면 추격 3.75→0.25) 일부 시나리오에서 M5가 늦어진다 |
| 회귀 | 기존 시험 225개 + 신규 `tests/test_avoid.py`(15), `tests/test_explore_online.py`(9) |

## 1. 현재 코드 분석 (이번 작업 전, 소스 기준)

| 구성 | 실제 동작 |
|---|---|
| 탐색(M3) | `mission/explore.py ViewpointTour`: 경기장을 `tour_nx × tour_ny`(**기본 5×5**; 시험 벤치는 3×3) 격자 시점으로 나눠 가까운 순서로 순회. **시점마다 제자리 360° 회전**(`mission.spin_w` 1.1 rad/s) |
| 면 순회 | `FaceTour`는 `CubeFinder`가 박스를 **4개 이상** 찾은 뒤(`manager._mode_explore_lattice`의 `len(cubes) >= 4`)에야 면 단위 방문을 시작한다 — 박스 하나를 찾아도 그 면을 곧바로 보러 가지 않는다 |
| 관측 지도 | `nav/grid.py OccupancyGrid`: 로그오즈 `L`, **미지(L=0)를 자유로 취급**(주석에 명시). 그래서 "본 곳/안 본 곳"을 이 지도로는 알 수 없고, 프런티어·정보 가치 계산이 불가능했다 |
| 객체 집계 | `perception/object_map.py`: 위치 기반 투표 합치기. 같은 면을 다른 시점에서 보면 위치가 달라 **이중 계수**가 난다(시뮬에서 정밀도 0.82) |
| M3 제출 | `_submit_m3_if_due`: `t ≥ t_base_cmd − 5 = 235 s`. 내용은 `omap.counts_by_sector()` |
| M5 사전 이동 | `t ≥ prestage_at = 222 s` → `Mode.STAGE`(상대 진영 중앙), `t ≥ 239 s` → `GOAL`. 이 시각 전에 탐색이 끝나야 한다 |
| M1 섹터 | `cmd.sectors`는 M1 제출 payload에만 쓰이고 탐색에는 안 쓰인다. 시뮬 채점은 **모든 섹터**의 객체를 정답으로 센다. 그래서 `explore.sector_priority=False`(켜면 가산점만 주고, 제외는 하지 않는다) |
| 안전 체인 | `SafetyLimiter`(정지 0.17 m/감속 0.45 m) → 깊이 가드 → 접촉(정체) 감지 → SAFE_STOP → STOP/HALT. 모든 출력이 `_apply(limit=True)` 또는 `_stop_output()`을 거친다 |
| 적 정보 | `perception/tracks.py UgvTracker`(카메라+UAV). `enemies()`는 팀이 불확실하면 적으로 본다. **경로계획은 적을 전혀 몰랐다**(그냥 동적 장애물). `get_uav()`의 실기 구현은 `None` 반환, UAV 영상 검출기는 코드에 없음 |
| 시뮬 상대 | 상대가 쏘지 않았다(HUNT OFF) → 피격 측정 불가였음 |

## 2. 구조 (계층)

```
임무 계층   EXPLORE(온라인 탐색기가 다음 관측 시점 선택) · STRIKE(M2) · STAGE · GOAL(M5)
              │  목표 점            ▲ 위협장(시간 층)·κ 로 비용/마감 반영
              ▼                     │
안전 계층   AvoidController (CLEAR→AWARE→EVADE→CLOSE) ── 소유권 이전/복귀 ──┐
              │ 안전 경유지(carrot)                                           │
              ▼                                                               │
계획 계층   Nav2 NavigateToPose  또는  내장 Navigator A*   (교체·제거 없음)   │
              ▼                                                               │
최종 필터   SafetyLimiter · 깊이 가드 · 접촉 감지 · SAFE_STOP · STOP/HALT ◀────┘ (항상 마지막, 항상 최우선)
```

### 2.1 "실제로 본 곳" 지도 — `perception/coverage.py` (신규)
- **`SeenMap`**(0.10 m): LiDAR 광선이 지나간 칸/끝점을 기록한다. 점유격자와 별개 — 미지를 자유로 보지 않는다. 프런티어(본 곳과 안 본 곳의 경계)와 시점의 *안 본 면적 이득*에 쓴다.
- **`CoverageMap`**: 점유 군집에서 박스 가설을 만들고(한 면만 보여도 외부 쪽을 격자로 추정), **면 장부**를 둔다. 면 상태: `UNSEEN / VIEWED_NO_DET / UNCERTAIN / CONFIRMED / EMPTY / UNREACHABLE / GIVEUP`.
  - 면마다 `views`(카메라가 실제로 볼 수 있었던 관측 수), `occluded_views`(가려서 못 본 시도), `arrive_attempts`, 분류 득표. "방문"이 아니라 **볼 수 있었는지**가 기준이다. 같은 위치·같은 방향의 반복 관측은 독립 관측으로 세지 않는다(시간·이동·카메라 방향 조건).
  - **이동한 박스**: 증거 칸이 다시 자유가 되면(격자 로그오즈가 깎임) 박스를 장부에서 지우고 `ObjectMap.drop_near`로 옛 위치 객체도 지운다. **일시적 가림만으로는 확정 관측을 지우지 않는다**(가림은 로그오즈를 안 낮춤).
  - **M3 집계**: `explore.m3_counting="ledger"` — 박스 면 1개 = 객체 1개, 섹터는 LiDAR 박스 중심으로 정한다. `"omap"`은 기존 방식.

### 2.2 온라인 탐색 — `mission/explore_online.py` (신규)
- **후보**: ① 미확인 면 앞 시점(거리 0.45/0.6/0.8/1.0/1.4 m × 옆 −0.6~+0.6 m) ② 프런티어 군집. 한 시점에서 **여러 면이 동시에 보이는지**(시야·거리·입사각 ≤70°·가림)를 `CoverageMap.face_visible`로 판정한다.
- **효용** = 정보(미확인 면 가중 + 안 본 면적) × (1 − min(0.9, `w_threat`·위험)) ÷ (이동시간 + 관측시간 + 오버헤드). 이동시간은 *위험 인지 A\** 추정(§2.4)으로, 관측시간은 `look`(한 방향) 또는 `spin`(360°) 중 싼 쪽.
- **마감**: 탐색 마감 = `prestage_at − 3 s`, 스테이징 마감 = `t_base_cmd − 4 s`(추정 스테이징 시간 포함). 도착+관측+스테이징이 예산을 넘는 시점은 거절(`rejected_time`).
- **안정화**: 히스테리시스(`switch_ratio` 1.3), tabu 20 s, 같은 시점 3회 반복 차단, 같은 자세 재방문 가중 ×0.15, 도착 시도 3회면 `GIVEUP`.
- **"박스 4개 규칙" 완화**: 박스 하나를 찾자마자 그 면의 시점이 후보로 들어가 효용으로 경쟁한다(고정 순회는 그대로 유지: `strategy="lattice"`).
- **좁은 곳 보호**: 제자리 360° 회전은 몸 둘레 `spin_clear_m` 안에 점유가 없을 때만, 있으면 한 방향 관측으로 바꾼다(스키드 조향 밀림으로 박스를 치던 문제).
- **깊이 3D 지도는 선택 사항**: 가림/시야 판정은 LiDAR 점유로 하며, 깊이가 있으면 `map3d` 층이 점유에 더해질 뿐 LiDAR+RGB만으로 동작한다.

### 2.3 위협 입력 — `perception/threat_board.py`, `perception/lidar_blobs.py` (신규)
| 단계 | 근거 | 위험 가중 |
|---|---|---|
| OBJECT | LiDAR 동적 군집만(움직이는 작은 물체) | `p_cons` 0.7 (적과 같은 보수 가중) |
| UGV | 카메라/UAV로 UGV 확인, 팀 미상·불일치 | 0.7 |
| ENEMY | UGV이고 `p_enemy ≥ 0.85` (안테나 색 투표, `ident`가 있으면 확정, 마지막 라벨이 오래되면 0.5 쪽으로 감쇠) | `max(p_enemy, 0.7)` |
| FRIEND | `p_enemy ≤ 0.10`이고 라벨 ≥2 | 0.15 (물리 점유는 그대로) |
- 위치 불확실도 σ = √(σ_obs² + (0.15·age)²) (σ_obs: LiDAR 0.06 / 카메라 0.08 / UAV 0.15 `[가정]`). 관측이 끊기면 ghost로 반경이 커지다가 `hold_track_s + ghost_s`(8 s)에 선형 감쇠 해제.
- **LiDAR 동적 군집**: 정적 구조는 같은 칸이 여러 번 맞아 굳는다(`h_static`=6). 아직 덜 맞은 칸의 새 반사를 연속 빔 군집으로 묶고, 크기 0.12~0.36 m + **양끝 깊이 불연속**(배경 앞 고립 물체) + **직진·속도(≥0.15 m/s)·순변위** 조건을 통과해야 한다. 한계: 멈춘 적은 정적으로 흡수된다(카메라/UAV에 맡김), 빠른 회전 중(|w|>0.8)·시작 3 s·벽 0.15 m 안은 건너뜀.

### 2.4 위협장과 경로 — Nav2에서 되는 것만 (`mission/threat_field.py`, `nav/risk_astar.py`)
- **물리 점유(body)와 피격 위험(risk)을 따로 둔다.** body_k: 시간 층 k(`layers`=4, `layer_dt`=0.75 s)의 예측 위치 반경 `r_body + k_σ·σ` + 우리 인플레이션 — **하드 차단**. risk_k: `가중 × 거리항 × 시야`(박스가 가리면 0.15) — **소프트 비용**. 근접 항 `close_k`는 붙는 것을 더 싫어하게 한다.
- **Nav2 현실**: 비용지도 마킹 점군은 움직이는 물체를 지우지 못하고(이미 확인), 동적 비용 계층은 C++ 플러그인(이 PC에서 빌드·시험 불가). 그래서 *Nav2 내부 비용지도를 바꾸는 척하지 않는다.* 선택한 방식은 **경유지(carrot)**: `risk_astar`(기존 A*와 같은 구조에 시간 층 비용만 더한 *추정기*)로 안전한 경로를 추정하고, 그 위 `carrot_m`(1.0 m) 앞 점을 `NavigateToPose`(또는 내장 A*) 목표로 보낸다. 경유지는 0.45 m 안으로 다가가기 전까지 고정하고, 새 경로가 옛 경로(남은 부분)보다 25 % 넘게 싸지 않으면 옛 경로를 유지한다(경로 뒤집힘으로 제자리 흔들림 방지).
- 내장 A*에서도 같은 코드가 쓰인다(`_nav_to`는 백엔드를 모른다). **WSL 실제 Nav2에서의 컨트롤러 흔들림은 아직 확인하지 않았다**(§7).

### 2.5 회피 제어기 — `mission/avoid.py` (신규)
- **수준**(진입 즉시, 해제는 한 단계씩 유지시간 후): AWARE(d<3.0 m 또는 TTC<6 s) → EVADE(d<1.6 m 또는 TTC<2.5 s) → CLOSE(d<0.8 m). 해제 문턱 = 진입 + 0.6 m(CLOSE는 +0.3), 유지시간 1.5/2.0/1.0 s, 최소 유지 1.0 s. 같은 적에 EVADE 재진입이 30 s에 4회 넘으면 일정 시간 AWARE로 격하.
- **AWARE**: 소유권 이전 없음. 임무의 `_nav_to`가 위험 인지 경유지를 쓰고 속도 ×0.85.
- **EVADE/CLOSE → 소유권 이전**(`_on_avoid_acquire`): 옛 목표 취소(`stack.clear_goal()` — Nav2 취소 + 이전 속도 폐기), `epoch += 1`, 사격 중단, 조준·관측 상태 초기화. 복귀(`_on_avoid_release`): 옛 목표를 이어가지 않고 새로 정한다. 지정표적은 3 s 쿨다운(회피 연기 합계 ≤30 s) 뒤 조준부터 다시.
- **후퇴 후보**: 지나온 길(breadcrumb, 0.25 m마다) + 주변 링(1.0/1.5/2.0 m × 16방위). *현재 시점*에 다시 검증한다 — ① 정적 자유 ② 적 예측 점유를 피한 위험 A* 경로 존재 ③ 도착 위험이 현재보다 낮음 ④ 경로 위 적과의 예측 거리가 크게 줄지 않음(적에게 접근하는 후퇴 배제; 박스 뒤로 숨어 위험이 절반 이하면 허용) ⑤ 연속 노출 ≤ 1.2 s. **무조건 후진하지 않는다**: 후진은 `reverse_max_m`(0.5 m) 이하·후방 LiDAR 여유·뒤쪽에 적이 없을 때만.
- **정지(HOLD)**: 맞을 수 있는 자리(위험 ≥0.5)에서는 서 있지 않는다(시뮬에서 얼어붙어 8발 맞은 사례로 고침). 뒤에서 쫓길 때는 정지·제자리 회전 금지, 임무 경로로 계속 전진.
- **막힘 복구 방향**: `recover_hint` — 적 쪽으로 돌지 않고, 적이 뒤 ±60° 1.5 m 안이면 후진 금지. `RECOVER`, `Navigator` 복구, `SafetyLimiter` 회전 선택에 전달(`NavStack.set_hint`, 근거리 CLOSE에서만 적용).
- **시간 우선순위**: `slack = (t_total − t) − 1.3·ETA − 8 s`, `κ = clamp(slack/25, 0, 1)`. 위험 가중 `w_risk·(0.35+0.65κ)`, slack ≤ 0이면 `0.05`배(곧장 감). **STAGE/GOAL에서는 EVADE가 소유권을 가져가지 않고**(경로만 위험 인지), CLOSE도 slack ≤ 0이거나 거점 1 m 안 돌진 조건(예측 노출 ≤1.2 s)이면 정지·후퇴하지 않는다. 회피가 구동을 쥔 시간이 60 s 창에서 25 s를 넘으면 15 s 격하(M3/M5를 무한정 미루지 않음).
- **STOP/SAFE와의 경쟁**: 순서는 `_serve`(STOP 래치) → `_enter_halt`(`avoid.reset()`, 목표·경유지 취소, 구동 0) → … `_avoid_gate`는 `_decide` 안이라 HALT/REPORT 틱에는 실행되지 않는다. `_enter_safe`도 `avoid.reset()`.

### M2 보완(온라인 탐색이 드러낸 기존 결함)
옆에서 처음 본 지정표적 면의 **법선이 틀려**(영상 추정이 '처음 본 방향'에 끌림) 스침각으로 쏴서 빗나갔다 → LiDAR 장부의 면으로 법선 보정(`_snap_face_normal`), 접근점을 "비어 있고 면 앞이 트인 점"으로 선정(`_strike_goal`, 박스 사이 좁은 틈 처리), 입사각 한계·사거리 제한(`strike_max_incidence_deg`, `fire_range_slack`), 표적을 놓치면 지도상 면 쪽으로 돌아 재탐색. 쏘던 면의 LED가 켜지면 같은 종류 다른 면이 미점등이어도 M2 완료.

## 4. 검증 결과 (시뮬, 같은 시드·같은 배치)

### 4.1 M3: 고정 5×5 순회 vs 온라인 탐색 (시드 1~6, 솔로 B2, 내장 A*, 3×3 격자 벤치)
`python scripts/compare_explore.py --seeds 1 2 3 4 5 6 [--shuffle 60 150]`

| 지표 | lattice / omap(기존) | lattice / ledger | online / ledger |
|---|---|---|---|
| M3 재현율 | 0.787 | **0.890** | 0.835 |
| M3 정밀도 | 0.823 | 0.977 | **0.988** |
| 이동거리(235 s까지, m) | 39.4 | 39.4 | **36.6** |
| 중복 방문 비율 | 0.028 | 0.028 | 0.037 |
| M5 도착률 / 시각 | 1.00 / 245.0 | 1.00 / 245.0 | 1.00 / 250.8 |
| 충돌 틱(평균) | 0.67 | 0.67 | 0.50 |
| M2 성공률 | 1.00 | 1.00 | 1.00 |

박스 재배치(60·150 s, 시드 1~4): 재현율 0.770 / 0.840 / 0.812, 정밀도 0.760 / 0.915 / 0.917, 이동거리 36.9 / 36.9 / 47.6 m.

**읽는 법(정직하게)**: 정밀도 개선(0.82→0.98)의 대부분은 *면 장부 집계*에서 나온다(고정 순회에 장부 집계만 붙여도 같다). 온라인 *탐색* 자체는 이동거리를 줄이고 충돌을 줄였지만 **재현율은 고정 순회보다 약 5 %p 낮고**, 박스 재배치 때는 이동거리가 오히려 늘었다. 원인 분석(시드 4·5): 벽을 향한 면, 마감 이후 남은 면, 후보가 마감 예산에 걸러지는 경우. 시뮬 6시드·표본 작음 — "개선"이 아니라 "집계 개선 + 동등한 탐색 + 이동거리 감소"로 읽을 것. 재현율이 중요하면 `explore.strategy="lattice"` + `m3_counting="ledger"` 조합이 시뮬에서 가장 좋았다.

### 4.2 적 회피: 회피 OFF(기준선) vs ON (시드 1~3 평균, 최종 코드, `scripts/compare_avoid.py`)
상대는 완벽 정보로 쫓아와 사정거리 안에서 조준·발사하는 *최악에 가까운* 시뮬 모델이다. 표 칸 = **평균 피격 횟수 / 평균 M5 도착 시각(s)**. M5 도착률은 모든 칸에서 3/3.

| 시나리오 | 기준선(회피 OFF) | 회피 ON(카메라+UAV+LiDAR) | YOLO 100 % 누락(UAV+LiDAR) | UAV 없음(카메라+LiDAR) | UAV 지연 2 s | LiDAR만 |
|---|---|---|---|---|---|---|
| S1 정면 추격 | 4.33 / 246.9 | **1.33** / 245.0 | 2.00 / 245.4 | 4.00 / 245.9 | 4.00 / 245.8 | 5.00 / 246.9 |
| S1b 정지 차단 | 2.33 / 244.7 | 2.00 / 246.4 | 2.67 / 253.1 | 1.33 / 245.0 | **6.00** / 247.8 | 2.33 / 246.2 |
| S3 후방 추격 | 5.33 / 244.5 | 5.67 / 249.6 | 2.33 / 248.0 | 2.33 / 246.2 | 5.00 / 247.6 | 3.67 / 245.2 |
| S3b 측면 추격 | 3.67 / 245.8 | 3.67 / 248.8 | 1.33 / 247.9 | 3.33 / 244.3 | **7.00** / 248.3 | 4.33 / 245.1 |
| S9 M2 조준 중 접근 | 4.33 / 245.2 | 4.00 / 251.5 (M2 0.67) | 4.67 / 248.9 | 5.33 / 247.4 | **6.33** / 246.2 | 4.33 / 246.5 |
| S10 M5 근처 차단 | 0.33 / 245.9 | 0.33 / 249.9 | 0.33 / 245.5 | 0.00 / 246.5 | 0.00 / 245.2 | 0.00 / 245.1 |
| S2 횡단 | 0.00 / 246.7 | 0.33 / 245.9 | 0.00 / 248.1 | 0.00 / 246.7 | 1.33 / 247.9 | 0.33 / 246.4 |

**읽는 법(정직하게)**
- 효과가 분명한 곳은 **정면 추격 S1**(피격 4.33→1.33, 최소거리 0.05→0.78 m, 노출 66→41 s)뿐이다. 최소 적과의 거리와 노출 시간은 대부분 시나리오에서 개선(예 S1b 노출 52→12 s)됐으나 **피격 횟수는 S3·S3b·S9에서 기준선과 같거나 높다**.
- **M5 시각은 기준선 대비 +0~6 s**, 도착률 100 % 유지. (회피가 정지·후퇴로 구동을 쥐면 M5가 30~45 s 늦어져서 STAGE/GOAL 중에는 소유권을 주지 않게 고친 결과다.)
- **미해결**: 후방·측면 추격(S3, S3b)에서 카메라를 켠 기본 설정이 오히려 카메라를 끈 변형(YOLO 100 % 누락: 2.33, 1.33)보다 피격이 많다. 원인은 규명하지 못했다(카메라 트랙과 UAV 트랙 융합 중복, 카메라 라벨 오판, 회피 중 팬 스윕 등을 의심). 표본 3시드라 우연일 수 있다.
- **degrade-safe 미충족**: UAV 지연 2 s는 오래된 위치에 반응하면 기준선보다 나빠진다(S1b 6.00, S3b 7.00, S9 6.33). `avoid.fresh_s`(1.6 s)로 오래된 관측에는 소유권을 못 주게 했지만 AWARE 경로 비용은 여전히 오래된 위치를 쓴다. LiDAR만 쓰는 변형도 S1·S3b에서 기준선보다 약간 나쁘다(5.00 vs 4.33, 4.33 vs 3.67). 그리고 UAV 지연·LiDAR만 변형에서는 M3 재현율이 0.47~0.62로 떨어졌고 M2 성공률 0.67 — 원인 미분석.
- 따라서 **회피는 '기본 켬'으로 확정할 근거가 부족하다.** 시뮬 근거로는 정면 추격에서만 이득이 확실하고, 센서가 좋지 않은 조건에서는 해가 될 수 있다. `avoid.enable=False`로 즉시 끌 수 있다(기존 동작과 동일).

## 8. 알려진 한계
- 온라인 탐색은 시뮬에서 재현율이 고정 순회보다 낮다(§4.1). 표본이 작아 순위가 바뀔 수 있다.
- LiDAR 군집 재현율은 낮다(시뮬 LOS 3.5 m 안 약 20 %). 멈춘 적은 정적으로 흡수된다 → *LiDAR만으로는* 정지한 사수를 못 본다. 카메라·UAV 없이 동작하는 것은 "추가 이득 없음"이지 "악화 없음"의 증명이 아니다.
- 위험 모델의 `r_core=2.2 m`(사정거리 안이면 거리와 무관하게 맞는다)는 시뮬 규칙이다. 처음 설계(0.9 m, 거리 감쇠)는 시뮬에서 중거리 피격을 과소평가했다.
- 시간 층 A*의 최적성은 보장하지 않는다. 상수는 대부분 시뮬 선택값이다.
