기록 출처: `recordings/wingbot_selfplay_20261109_candidate02/*/risk_worker_summary.json`. 제출→발행은 센서 촬영→Agent 사용 지연과 다르다. worker 오류는 모두 0이었다. 실제 트랙 수는 p95 약 12–18개여서 6개 트랙만으로 성능을 판단할 수 없다.

## 구현과 수치 보존

- 불변 광선 방향·샘플을 최대 16개 조합으로 캐시한다. 관측 점유 지도와 로봇 위치를 실행 간 캐시하지 않는다.
- 물리 거리 계산에 이미 사용한 좌표 차이·거리를 가시성 계산에서도 재사용한다.
- 같은 트랙의 예측 위치가 시간층 사이에서 정확히 같을 때만 비용 항을 재사용한다. 정지 물체와 3초 외삽 한도에 도달한 관측이 해당된다. 각 층의 신선도·물리 차단 여부는 따로 계산한다.
- 180개 가시성 광선, 네 시간층, 물리 안전거리, 가중치, 누적 순서, worker 주기와 긴급 갱신 규칙은 유지한다.
- 넓은 배열 일괄 처리는 NumPy 스칼라 정밀도 때문에 가시성 경계가 달라지는 반례가 있어 폐기했다.

Windows 관련 시험 42개와 WSL 관련 시험 55개가 통과했다. 이후 추가한 기존 모드 비교를 포함한 수치 보존 시험 19개도 WSL에서 통과했다. 참조 구현 대비 body/risk/close/mind를 비트 단위로 비교했다. 새로운 실제 경기 재검증은 별도로 필요하다.

## 오프라인 부하 시험

WSL Python에서 여섯 프로세스를 실행하고, 각각 위험장 thread와 10ms 중 9ms 동안 GIL을 점유하는 합성 Python 제어 작업을 함께 돌렸다. 실제 Agent 실행을 재생한 것은 아니다. 격자는 6×4.8m, 5cm 간격이며 기존 0.1m 여백 때문에 124×100칸이다. 매 프로세스 30회, 단독 프로파일은 50회다.

| 입력 | 이전 단독 p95 | 개선 단독 p95 | 이전 6개 worker 계산 p95 범위 | 개선 범위 |
|---|---:|---:|---:|---:|
| 18개 모두 최신·이동 | 45.3ms | 49.9ms | 691.6–726.5ms | 403.8–524.6ms |
| 최신 6개 + 3.1초 경과 12개 | 47.6ms | 20.6ms | 637.3–700.7ms | 341.8–356.8ms |

오래된 트랙이 포함된 경우 단독 계산 비용이 약 절반으로 줄었다. 과도한 합성 GIL 부하에서는 개선 후에도 예산을 넘는다. 최신 이동 트랙만 있는 단독 측정은 유의미한 개선을 보이지 않았다. 실제 성능은 다음 실행의 트랙 수·관측 나이·CPU 부하와 함께 확인해야 한다. 스케줄링 지연이 지배적이면 추가 배열 최적화만으로 100ms를 보장할 수 없다. Jetson 또는 실기 측정 결과가 아니다.
