# 교착 방지 후보 구현과 적용 범위

새 정책은 `config/deadlock_candidate.json` 또는 시험 실행기의 `progress` 변형으로 켠다. 일반 실행의 `progress.enabled`는 아직 false다. 초기 A/B에서 M2+M3는 올랐지만 M5와 교착 기준을 통과하지 못했으므로, 기존 정책을 검증 없이 교체하지 않았다. 기본값 채택 여부와 실제 시험 수는 `DEADLOCK_DIAGNOSIS.md` 및 각 실행의 결과 파일이 기준이다.

## 제어 구조

기존 임무 FSM은 유지한다. `mission/deadlock.py::DeadlockMixin`이 감지 뒤, 임무 선택 전에 단일 진척 감시기와 자세 제어기를 갱신한다. `mission/manager.py`는 이 결과를 경로 선택, 관측, 구동 및 제한적인 막힘 해소 사격에 반영한다. 로봇마다 독립 Agent/HAL이 있고, 연합 간 메시지나 시뮬레이터의 실제 좌표를 제어 입력으로 사용하지 않는다. 실제 좌표는 녹화와 평가에서만 사용한다.

| 축 | 상태·전이 | 구현 |
|---|---|---|
| 위협 | L0~L3, 상승 즉시·하강 조건 3초 유지 후 한 단계 | `mission/posture.py::PostureController` |
| 자세 | 기본 AVOID, CM·정체 6초·무적·GOAL이면 ENGAGE_OK, L3와 피격 2회 이상이면 COVER | 같은 제어기 |
| 결정 유지 | 4초 또는 순변위 0.6m, 자세 최소 3초, 진동 시 커밋 | 같은 제어기 및 `nav/progress.py` |
| 피격 예외 | 3회부터 ENGAGE_OK 해제. 무적·GOAL 마지막 1m 예외 | 같은 제어기 |
| 정체 | 3초 재계획 → 6초 교전 감수 → 9초 물리 막힘 후퇴/우측 통행 → 13초 목표 포기 | `nav/progress.py::ProgressMonitor` |
| 재시도 | 30초 뒤 후보 복귀, 같은 목표 두 차례 포기 시 해당 경기에서 제외 | 같은 감시기 |

안전상 즉시 필요한 위협 상승/피격 예외는 진동 억제보다 우선한다. 따라서 진동 억제 구현만으로 모든 장면에서 10초 내 전환 3회 이하가 보장되는 것은 아니다. 기록된 초과 사건을 그대로 불합격으로 센다.

진척은 남은 경로 0.15m 감소, 새 면 관측, 사격 진행 또는 도착이다. 바퀴 명령이나 경로 재계산만으로 진척을 만들지 않는다. WAIT, 정상 STAGE, 관측, 발광, 규정상 주행 잠금은 정상 대기로 구분한다. 별도 평가 감시기는 목표를 계속 바꾸는 경우에도 12초 무진척을 숨기지 않는다.

후보 04는 남은 거리 계산에 쓸 경로를 현재 목표와 대조한다. 오래된 위험 경로가 다른 목표로 끝나면 탐색 경로와 지역 항법 경로도 검사한 뒤에만 직선 거리로 대체한다. 고정 위치에서 캐시 소멸만으로 2m가 6m로 뛰던 재현 사례를 수정했다. 실제 후보 03 기록에서 직선 대체가 정체 중 4.8초를 차지했으므로 이 오류 하나가 전체 정체의 원인이라고 판단하지 않는다.

STAGE의 공통 대기점이 관측된 구조물이나 신선한 UGV로 막혔으면 13초 포기를 기다리지 않고 대체 대기점을 고른다. 자기 센서가 확인한 연결된 빈 공간에서 같은 차체 간격을 적용하며 아군 행동이나 통신에 기대지 않는다. 선택한 대기점은 계속 유지하고 M5 배정 거점은 바꾸지 않는다. 안전한 대기점을 찾지 못한 정지는 정상 대기로 숨기지 않는다. 이 변경의 전체 경기 효과는 후보 04 실행 결과로 별도 평가한다.

## 경로와 감지

`mission/risk_worker.py`가 위험 층을 별도 스레드에서 5Hz로 만들며 새 LiDAR 입력은 즉시 갱신을 요청한다. 2D 가상 시계 시험만 같은 계산을 동기 실행한다. 위험·피격 이력·병목은 유한한 비용이다. 물리 장애물, 3:45 이후 자기 거점 금지, 신선한 실제 UGV의 최소 간격만 차단에 사용한다.

`mission/manager.py::_risk_carrot`는 위험 경로와 짧은 경로를 비교한다. 관측하지 못한 박스 뒷면 내부를 안전한 우회로로 취급하지 않도록 유한한 미관측 공간 비용을 추가했다. 미관측 칸은 계속 통과 가능하다. 이전 경로를 유지할 때도 최신 충돌 지도와 같은 비용을 확인한다. 이 수정의 통로 통과 효과는 별도 시험 결과로 판단한다.

통로 재현에서는 비용만 올려도 해결되지 않았다. A*가 2.25초 후의 상대 위치를 10초 이상 뒤에도 같은 물리 장애물로 적용한 것이 원인이었다. 후보는 관측 나이와 예측 시간을 합친 1.6초 범위에서만 미래 차체 위치를 강제하고, 더 먼 미래는 위험 비용으로 남긴다. 실제 접근 시에는 새 센서로 재계획하고 차체 간 0.30m 간격과 LiDAR 정지를 계속 강제한다. LiDAR 정지 뒤 감속 램프가 전진 명령을 되살리던 문제도 마지막 구동 제한에서 차단했다. 이 수정의 최초 대칭 통로 시험은 R2 14.60초/B2 14.70초 도착, 충돌 0으로 통과했다. 모든 경기 시나리오의 합격을 뜻하지 않는다.

`perception/lidar_blobs.py`는 CPU에서 정적 반사면을 제외하고 0.12~0.40m 군집을 추적한다. 긴 벽을 먼저 군집화해 벽의 일부만 로봇 크기로 잘리는 오탐을 줄였다. `perception/threat_board.py`는 실제 카메라 슬리브 색과 UAV 영상 검출을 연결한다. 미상은 사격 대상이 아니며 충돌하는 색/식별 증거도 확정 상대로 취급하지 않는다.

실제 ROS에서는 로컬 LiDAR 위치 추정이 주 경로다. 바퀴 방향과 IMU가 어긋난 B3 사례를 조사하여 상대 IMU 회전량을 바퀴 초기 방향에 맞추는 선택적 융합을 추가했다. 전역 실제 방향을 초기값으로 주입하지 않는다. 신선하지 않거나 유효하지 않은 IMU는 바퀴 입력으로 복귀한다. 이 기능 역시 후보 시험에서만 켠다.

## 사격과 규칙

`engage_ugv=False`를 유지한다. `engage.fire_on_blocker`도 A/B 전까지 기본 false다. 켠 경우라도 ENGAGE_OK·정체 2단계·진로를 실제로 막는 상대·신뢰도 0.8·거리 0.6~1.5m·실제 수광부·안전한 사선·무기 잠금 해제·대상별 10초 간격이 모두 필요하다. M2 미완료 시 3발을 보존하며 M2 실패를 완료로 오해하지 않는다. 미상/아군 또는 식별이 사라진 상대에게 발광을 지속하지 않는다.

수광부 조건은 추정된 박스 중심으로 대체할 수 없는 실제 `sensor_locked` 증거다. 카메라 신선도도 추론 완료 시각이 아닌 촬영 시각으로 확인한다. 이미 허용된 발광은 사격 자체가 진척으로 기록되어 정체 단계가 초기화되어도 정렬을 유지하며, 새 표적·식별 소실·사선 위험·잠금이 생기면 중단한다. 발광 전 조준 대기는 노출 정지 한도에 포함한다.

Gazebo 심판은 2초 연속 수광부 조사, 피격 후 10초 무적/무기 잠금, 4회째 주행 정지를 반영한다. 4회 이후 체력이 0이라고 영구 무적이 되는 오류를 수정했다. 아군 광선도 피격 판정에 포함한다. 공식 대회 서버의 동작을 검증한 결과라는 뜻은 아니다.

## 설정과 현장 확인

| 설정 | 후보 기본값 |
|---|---|
| `risk.w` | L0 0.5 / L1 1.5 / L2 4 / L3 10 / engage 0.3 |
| `risk.team_weight` | 상대 1.0 / 미상 0.7 / 아군 0.3 |
| `risk.range_m` | 3.0m, 현장 실측 필요 |
| `risk.max_exposed_dwell_s` | 1.5초 |
| `risk.dwell_cap_from_hits`, `avoid.evade_min_hits` | 2회 |
| `engage.min_clearance_m` | 차체 가장자리 간 0.30m |
| `progress.stall_*_s` | 3 / 6 / 9 / 13초 |
| `posture.commit_s`, `commit_dist_m`, `min_dwell_s` | 4초 / 0.6m / 3초 |
| `threat.lidar_crosstalk.enabled` | false, 실기 미검증 |
| `hal.imu_heading_fusion` | 일반 false, Gazebo 후보에서 선택적 true |

서빈님 비용표는 제공되지 않아 반영 여부를 확인하지 못했다. `risk.cost_table`로 대체할 수 있다. 실제 LiDAR 토픽·거리 오차·수광부 위치·깊이 카메라 제공 여부·Jetson 처리 지연은 현장에서 확인해야 한다. 깊이 입력이 없어도 동작하도록 시험한다. UAV의 오래된 영상이나 403 응답은 로컬 센서 동작을 중단시키지 않는다.

선택 항목인 아군의 팬틸트 방향별 사선 비용은 아직 구현하지 않았다. 현재 영상 추적에 아군의 발광 자세를 확정할 관측값이 없기 때문이다. 일반적인 아군 노출 비용 0.3과 병목 점유 비용은 적용하지만, 설정에 `ally_fire_lane` 이름이 있다는 이유로 방향별 사선 회피가 구현되었다고 표시하지 않는다.

LiDAR 간섭과 카메라 IR 섬광은 Gazebo로 검증할 수 없다. `tools/lidar_crosstalk_probe.py`, `tools/camera_ir_probe.py`와 `LIDAR_CROSSTALK_STUDY.md`에 실측 절차를 준비했다. 실측 전에는 기능을 켜거나 성능 수치를 제시하지 않는다.

## 검증 한계

각 영상과 결과에는 실행한 코드와 시나리오를 구분한다. `compare_sim.py`는 2D 센서 모델이며 Gazebo 영상으로 표시하지 않는다. `run_wingbot_selfplay.py`는 실제 Gazebo RGB/LiDAR/odom/IMU 여섯 개 입력을 각각 독립 Agent에 연결한다. 이전의 좌표 기반 훈련 상대 영상은 6-Agent 자가 대전 증거에서 제외한다.

2D 20시드 및 Gazebo 10시드 행렬의 실행 계획과 완료 건수는 분리한다. 프로세스 종료 성공, 총 그림 수 일치, 파일 생성만으로 교착 0이나 M3 모든 개별 면 관측을 선언하지 않는다. 특히 Gazebo의 적층 표적은 같은 평면 좌표의 서로 다른 높이를 개별적으로 식별한 증거가 필요하다. 아직 해당 높이별 커버리지 증명이 없으면 미검증으로 둔다.

대회 원문과 실제 임무코드는 외부에 전송하지 않는다. 실제 임무코드는 `MAICON_CODE` 환경변수로만 받고, 예시에는 `K7M2Q9XA`만 사용한다. 시험용 로컬 API 인증값은 보고서에서 숨긴다.
