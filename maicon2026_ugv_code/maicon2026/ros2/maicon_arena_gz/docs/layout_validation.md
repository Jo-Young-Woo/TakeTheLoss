# 배치 생성과 검증 범위

이 패키지는 제공된 `config/arena_spec.yaml`과 `config/layouts/layout_default.yaml`을 원본 그대로 보존한다. 기본 배치는 사전자료 렌더를 바탕으로 한 추정 배치이며, 공식 경기의 실제 장애물 위치를 뜻하지 않는다. 경기장 좌표의 원점은 6.00 × 4.80 m 바닥 인쇄의 중심이다. 기존 실험의 0부터 시작하는 좌표나 벽 포함 외곽 치수를 섞지 않는다.

## 생성 규칙

`gen_layout.py --seed 2026 --count 20 --output <directory>`는 20개 배치 파일을 만든다. `--count`는 큐브 개수가 아니다. 제공 템플릿의 덩어리 모양과 물리적 큐브 수를 유지하면서 20 cm 격자 단위로 덩어리를 이동시키고 면 이미지를 다시 배정한다. 같은 시드·같은 입력·같은 이미지 파일 목록은 같은 결과를 만든다. 새 기본 배치를 대신 만들거나 원본 기본 배치에 덮어쓰지 않는다.

검사에서 탈락한 이동은 취소한다. 통과할 때까지 이격 조건을 줄이거나, 검사하지 않은 위치를 대신 쓰는 동작은 없다. B/R의 대응 덩어리는 X=0 기준으로 함께 이동한다. 각 진영의 세 줄에는 radar/comms/outpost 표적이 하나씩 있고, 대응 표적 위치와 면 방향을 대칭으로 배정한다. 대응 표적의 종류까지 같게 하는 것은 현장 확인이 필요한 가정이다.

각 덩어리는 면끼리 붙은 큐브들의 연결 집합이어야 한다. 같은 이름만 붙여 떨어진 큐브들을 하나의 덩어리로 간주해 이격 규칙을 피할 수 없다. 서로 다른 덩어리, 벽, 센서 박스·중앙 패드 등 고정 설비 사이에는 YAML의 `cubes.min_clearance`를 적용한다. 고정 센서 박스 자체가 벽에 붙어 있는 것은 제공 사양의 명시된 예외다. 간격은 큐브의 실제 사각형 외곽 사이 최단 유클리드 거리이며, L자 덩어리의 비어 있는 모서리를 충돌체로 채우지 않는다.

일곱 구역에 모두 큐브와 적어도 한 개의 실제 M3 이미지를 배정한다. 큐브의 전체 바닥 면적이 해당 구역 안에 있어야 한다. 옆면 N/E/S/W는 각각 +Y/+X/-Y/-X이며 윗면과 밑면은 검정이다. 접한 옆면은 `hidden` 또는 `blank`만 허용한다. 생성기는 M3 정답을 최종적으로 노출된 면에서 다시 계산한다. `targets_summary`도 최종 이미지 배정에서 다시 만든다.

이미지 변형은 예를 들어 `m3:tank@field2.jpg`로 저장한다. 실제 파일은 `media/textures/faces/m3_tank/field2.jpg`이다. 해당 종류의 폴더에 `.jpg`, `.jpeg`, `.png` 변형이 있으면 시드에 따라 고른다. 폴더가 없으면 제공된 `m3_tank.jpg`를 쓴다. `@` 뒤 파일명은 M3 종류와 계수에 영향을 주지 않는다. 경로 탈출이나 외부 이미지는 허용하지 않는다.

## 로봇 접근성의 의미와 한계

큐브마다 단순히 “숨겨지지 않은 면”이라고 판단하는 것으로 끝내지 않는다. UGV 바닥 형상을 감싸는 원의 반경에 바닥 격자 한 칸의 1/20을 더하고, 모든 장애물을 그 반경만큼 확장한다. 격자 해상도는 바닥 한 칸의 1/8(현재 2.5 cm)이다. 실제 여섯 출발 위치에서 연결된 자유 공간을 계산하고, 각 M3·표적 면 앞에 로봇이 설 수 있는 접근 자세가 있는지 확인한다. 닫힌 고리 구조물 안쪽처럼 면은 노출되었어도 로봇이 들어갈 수 없는 곳에는 이미지를 배정하지 않는다.

이는 방향 전환 시에도 충돌하지 않는 보수적인 평면 접근 검사다. 실제 카메라의 화소 수, 조명, 반사, 인식 정확도, 센서 높이에 대한 검증을 대신하지 않는다. 특히 쌓은 큐브의 윗층 이미지는 카메라 높이·틸트 범위를 별도로 검증해야 한다. 이 한계는 검사 결과의 경고에도 남긴다.

`stack: 2`는 같은 XY에서 2층이며, `level: 1`은 바닥에서 한 층 위에 시작한다. 기본값은 각각 1과 0이다. 밑층에 같은 크기의 큐브가 없으면 지지되지 않은 층으로 거부한다. 한 입력 항목의 면 배정은 그 항목의 모든 층에 적용된다. 층마다 서로 다른 사진이 필요하면 각 층을 별도 항목으로 적고, 같은 덩어리 이름과 `level`을 사용한다. 충돌체는 정확한 큐브 합집합을 직육면체로 합치며, 시각 요소는 물리적 큐브마다 하나다.

## 검사 결과를 해석하는 법

`check_world.py`는 생성기 메타데이터 JSON을 신뢰하지 않고 실제 SDF를 읽는다. model/link/geometry 위치를 합성하고, OBJ 꼭짓점과 스케일을 읽어 최종 치수를 YAML과 ±1 mm로 비교한다. 바닥·벽·8개 센서 박스·2개 중앙 패드·큐브·표적 LED를 확인한다. 이름이 다른 추가 충돌체, 누락, 비정상 회전, 공유 메시의 반전 스케일도 거부한다.

UGV를 제외한 실제 SDF 노드 수에 대해 충돌체 40개, 시각 요소 80개, 텍스처 30개, 텍스처 긴 변 2560 px 제한을 적용한다. Ogre 2의 PBR 이미지와 Ogre 1의 재질 스크립트 이미지가 같은지도 검사한다. 외부 네트워크/Fuel 경로, 비박스 정적 충돌체, 검증하지 못한 상대 프레임이나 중첩 정적 모델은 통과시키지 않는다.

`overlay.py`는 동일한 YAML을 제공 바닥 이미지 위에 겹친 좌표 검증 도구다. `--show-access`는 M3·표적의 접근 가능한 관찰 위치를 함께 표시한다. 이 이미지는 **Gazebo에서 실제로 촬영한 화면이 아니다**. 실제 렌더와 기준 이미지의 1 cm 정합, 사진의 상하·좌우 방향, RTF·GUI FPS·기동 시간은 별도의 실제 실행 결과로 확인해야 한다. 정적 검사와 단위 테스트 통과만으로 그 성능 또는 렌더 검증까지 통과했다고 기록하지 않는다.

추정값을 현장 값으로 바꿀 위치는 `arena_spec.yaml`의 `assumed` 주석 및 프로필 YAML, 생성 배치의 `meta.assumptions`다. 특히 벽 두께, 센서 높이·빔 위치, 모서리 센서 박스 형태, 중앙 패드의 실제 용도, 출발 자세, 거점 이름과 줄 번호 관계, UAV 카메라 자세·화각, UGV 가로/세로 방향과 카메라 장착 높이를 확인해야 한다. 바닥 두께 2 cm는 사용자 요청의 물리 모델링 값이며 실물 바닥 측정값이 아니다.
